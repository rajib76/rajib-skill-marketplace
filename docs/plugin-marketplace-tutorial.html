01What a plugin is

Docs: Plugins overview · Plugin components · Manifest reference

A plugin is a folder that bundles extensions for Claude Code so you can install them as one unit. It can hold skills, slash commands, subagents, hooks and MCP servers. A file at .claude-plugin/plugin.json gives the plugin its name and version.

Skills, subagents, hooks and MCP servers all work on their own without a plugin. For example, a skill saved in ~/.claude/skills/ works in every project on your machine. Use a plugin when you want several of them packaged as one unit, to share with teammates, install in many projects, or publish as versioned releases.

ComponentWhere it livesWhat it does
Manifest.claude-plugin/plugin.jsonName, version, description and author. Required.
Skillsskills/<name>/SKILL.mdInstructions Claude loads when the skill's description matches the task. You can also invoke one as /plugin-name:skill-name.
Commandscommands/<name>.mdSlash commands you type yourself.
Agentsagents/<name>.mdSubagents with their own prompt and tool list.
Hookshooks/hooks.jsonShell commands that run on events, such as before a tool call.
MCP servers.mcp.jsonTool servers Claude Code connects to while the plugin is enabled.
Hooks modulesee modsHooks written as JavaScript functions that can also draw panes and add commands. A plugin with one is called a mod.

The smallest useful plugin is a manifest plus one skill. This is my-first-plugin from the local example:

my-first-plugin/
my-first-plugin/
├── .claude-plugin/
│   └── plugin.json
└── skills/
    └── greetings-skill/
        └── SKILL.md
.claude-plugin/plugin.json
{
  "name": "my-first-plugin",
  "description": "A greeting plugin to learn the basics",
  "version": "1.0.0",
  "author": {
    "name": "Rajib Deb"
  }
}
skills/greetings-skill/SKILL.md
---
name: greetings-skill
description: Use this skill to greet the user
---

When a user says HI, ask for the name and then say HI <Name>
The description decides when a skill runs

Claude reads every installed skill's description and loads the full SKILL.md only when the task matches. Say what the skill does and when to use it, for example "Greet the user. Use when the user says hi or hello."

Enabled plugins cost context in every session

The docs point out that an enabled plugin is part of every session, not only the ones where you use it. The name and description of each skill, agent and command sit in Claude's context on every turn, its MCP servers run alongside each session, and its hooks fire on their events. Everything a plugin runs, it runs as you. Disable plugins you aren't using, and see Plugin security and trust before installing one from someone else.

While you're developing a plugin you don't need a marketplace at all. Load it straight from its folder with claude --plugin-dir ./my-first-plugin.

02What a marketplace is

Docs: Get plugins from a marketplace · Install and manage plugins

A marketplace is a catalog of plugins. It's a single file, .claude-plugin/marketplace.json, that names the marketplace and lists each plugin with a source saying where to get it. The marketplace doesn't run anything itself. It tells Claude Code what's available and where to download it.

You publishMarketplaceA repo or folder with marketplace.json
User runsAdd/plugin marketplace add copies the catalog locally
User runsInstall/plugin install name@marketplace fetches the plugin from its source
Claude CodeLoadsSkills, commands and hooks are active in the next session

A plugin is always installed by its full id, plugin-name@marketplace-name. Both parts come from the name fields in the JSON files, not from folder or repo names. In the local example below, the folder is rajib_marketplace but the marketplace is named my-marketplace, so the id is my-first-plugin@my-marketplace.

Claude Code adds Anthropic's official marketplace, claude-plugins-official, the first time you start an interactive session. Anthropic's marketplace names are reserved for repos under github.com/anthropics/, so your own marketplace is a third-party one and can't use them. A plugin marketplace is also different from Claude Marketplace, the website on claude.com.

Install scopes

When you install, you choose who gets the plugin:

ScopeSaved inWho gets it
user~/.claude/settings.jsonYou, in every project. This is the default.
project.claude/settings.json (committed)Everyone who works in the repo. Each collaborator still installs it on their own machine.
local.claude/settings.local.json (not committed)Only you, only in this repo.

Plugins from a git or URL source are copied into a cache under ~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/. Plugins from a marketplace you added as a local folder load in place from that folder. Cloud sessions, including claude.ai/code, don't load the plugins in your local settings.

03Two ways to organize a marketplace

Docs: Choose a plugin source · Plugin sources reference

The source field on each plugin entry decides the layout. This tutorial builds one marketplace of each kind.

A · Plugins inside the marketplace

~/PycharmProjects/rajib_marketplace
  • "source": "./plugins/my-first-plugin"
  • One repo to maintain; a single commit changes catalog and plugin together
  • Works from a local folder, before anything is pushed
  • Best for a personal or team collection

B · Each plugin in its own repo

github.com/rajib76/rajib-skill-marketplace
  • "source": {"source": "url", "url": "https://github.com/…/hello-plugin.git"}
  • Each plugin has its own history, issues and owners
  • The marketplace can list plugins written by other people
  • Best when plugins are maintained separately

Source types

SourceExampleNotes
Relative path"./plugins/my-first-plugin"Path inside the marketplace repo. Must start with ./.
url{"source": "url", "url": "https://github.com/rajib76/hello-plugin.git"}Any git URL. An HTTPS URL clones over HTTPS, so users don't need SSH keys.
github{"source": "github", "repo": "rajib76/hello-plugin"}Shorthand for GitHub. Claude Code tries SSH first, then HTTPS; see Troubleshooting.
git-subdir{"source": "git-subdir", "url": "rajib76/monorepo", "path": "tools/my-plugin"}A plugin in a subfolder of another repo, such as a monorepo. url takes a git URL or owner/repo.
archive{"source": "archive", "url": "https://…/my-plugin.zip"}A zip downloaded over HTTPS. Users need no git and no account. Pin it with sha256.
npm, commandsee referenceAn npm package, or a folder produced by running a command on the user's machine.

The github, url and git-subdir sources can also take "ref" (a branch or tag) or "sha" (an exact commit) to pin the version users get.

Keep the entry name and the plugin name the same

The entry name in marketplace.json is the install id. The name in plugin.json is the prefix on the plugin's skills. The docs say most failed installs come from these two names differing, or from a relative path written from the wrong folder. Write relative paths from the marketplace root (the folder that contains .claude-plugin/), and never use ...

04Build a local marketplace

Docs: Create a plugin · Create a marketplace

This rebuilds rajib_marketplace from scratch. Nothing needs to be on GitHub yet.

Step 1 · Create the folders

terminal
mkdir -p rajib_marketplace/.claude-plugin
mkdir -p rajib_marketplace/plugins/my-first-plugin/.claude-plugin
mkdir -p rajib_marketplace/plugins/my-first-plugin/skills/greetings-skill
cd rajib_marketplace

Step 2 · Write the plugin

Save the plugin.json and SKILL.md from section 01 into plugins/my-first-plugin/. The finished layout:

rajib_marketplace/
rajib_marketplace/
├── .claude-plugin/
│   └── marketplace.json          ← the catalog
└── plugins/
    └── my-first-plugin/
        ├── .claude-plugin/
        │   └── plugin.json       ← the plugin manifest
        └── skills/
            └── greetings-skill/
                └── SKILL.md

Step 3 · Write the catalog

.claude-plugin/marketplace.json
{
  "name": "my-marketplace",
  "description": "Plugins for my team",
  "owner": {
    "name": "Rajib Deb"
  },
  "plugins": [
    {
      "name": "my-first-plugin",
      "source": "./plugins/my-first-plugin",
      "description": "A greeting plugin to learn the basics"
    }
  ]
}

Fields: name is the id users type after @. Use lowercase with hyphens. owner needs a name; email is optional. Each entry in plugins needs a name and a source.

Step 4 · Validate

terminal
claude plugin validate .
# ✔ Validation passed

Run the same command on a plugin folder to check its plugin.json. Validation checks JSON syntax, required fields, naming rules and paths containing ... It doesn't fetch remote sources, so a wrong repo or a missing folder only shows up when you install.

Step 5 · Add it and install

From your shell, add the folder by path, install by id, and check what loaded:

terminal
claude plugin marketplace add ~/PycharmProjects/rajib_marketplace
claude plugin install my-first-plugin@my-marketplace
claude plugin list
claude plugin details my-first-plugin

Inside a session, /plugin marketplace add does the same thing, and /plugin install my-first-plugin@my-marketplace opens the plugin's details in the /plugin panel, where you confirm the install and pick a scope.

Start a new session and say HI. Claude asks for your name and greets you. You can also call the skill directly with /my-first-plugin:greetings-skill.

Edits to a local marketplace

A marketplace added from a local folder loads relative-path plugins from that folder, so your edits take effect at the next session start, or right away with /reload-plugins. You don't need to bump version. People who install from the hosted copy get a cached copy instead; see Release updates.

05Publish on GitHub

Docs: Host and maintain a marketplace · Publish and distribute a plugin

To share a marketplace, push its folder to a GitHub repo. Users add it with the owner/repo shorthand, and relative plugin paths keep working because Claude Code clones the whole repo.

terminal
cd rajib_marketplace
git init -b main
git add -A
git commit -m "Create my-marketplace"
gh repo create rajib76/rajib_marketplace --public --source . --push

Anyone can now run:

claude code
/plugin marketplace add rajib76/rajib_marketplace
/plugin install my-first-plugin@my-marketplace

Claude Code takes the marketplace name from the name field in marketplace.json, not from the repo name. marketplace add accepts other forms too:

HostUsers run
GitHub/plugin marketplace add rajib76/rajib_marketplace
GitHub, pinned to a branch or tag/plugin marketplace add rajib76/rajib_marketplace#stable
GitLab, Bitbucket, other git hosts/plugin marketplace add https://gitlab.example.com/team/plugins.git
Hosted file/plugin marketplace add https://plugins.example.com/marketplace.json
Shared folder/plugin marketplace add /Volumes/shared/claude-plugins

A marketplace added as a bare marketplace.json URL downloads only that file, so relative-path entries fail. Use a git repo, or give every entry a remote source. Also keep plugin files out of Git LFS, because the clone never downloads LFS content.

Public or private

A private repo works for anyone whose git can already clone it without prompting. Claude Code runs git with prompts turned off and has no token of its own, and marketplace.json has no field for credentials. For HTTPS on GitHub, users run gh auth login and then gh auth setup-git. For SSH, the key must be loaded in ssh-agent.

06Plugins in their own repos

Docs: Add plugin entries · Plugin entry fields

The second example, rajib76/rajib-skill-marketplace, holds only the catalog. Its one plugin, hello-plugin, lives in rajib76/hello-plugin.

Step 1 · Create the plugin repo

A plugin repo has the plugin at its root:

hello-plugin/ (its own repo)
hello-plugin/
├── .claude-plugin/
│   └── plugin.json
├── skills/
│   └── hello/
│       └── SKILL.md
└── README.md
skills/hello/SKILL.md
---
name: hello
description: Greet the user warmly. Use when the user says hello, asks for a greeting, or wants to test that hello-plugin is installed.
---

# Hello

Greet the user by name if you know it, in one or two friendly sentences.
Then confirm that the `hello-plugin` from the rajib-skill-marketplace is installed and working.
terminal
cd hello-plugin
claude plugin validate .
git init -b main && git add -A && git commit -m "Initial hello-plugin"
gh repo create rajib76/hello-plugin --public --source . --push

Step 2 · Point the catalog at it

The marketplace repo contains only .claude-plugin/marketplace.json and a README:

rajib-skill-marketplace/.claude-plugin/marketplace.json
{
  "name": "rajib-skill-marketplace",
  "owner": {
    "name": "Rajib Deb"
  },
  "metadata": {
    "description": "Rajib's Claude Code plugins, each sourced from its own GitHub repo",
    "version": "1.0.1"
  },
  "plugins": [
    {
      "name": "hello-plugin",
      "description": "Starter plugin with a friendly greeting skill",
      "source": {
        "source": "url",
        "url": "https://github.com/rajib76/hello-plugin.git"
      },
      "category": "examples",
      "keywords": ["starter", "example", "skill"]
    }
  ]
}

category and keywords are optional. They help people find the plugin in the /plugin Discover tab. The entry has no version because the plugin's own plugin.json sets it. The docs warn against setting it in both places: plugin.json silently wins, and validate reports a mismatch.

Step 3 · Validate, push and install

terminal
claude plugin validate .
git add -A && git commit -m "Add hello-plugin" && git push
claude code
/plugin marketplace add rajib76/rajib-skill-marketplace
/plugin install hello-plugin@rajib-skill-marketplace

Adding more plugins

  1. Create a repo with .claude-plugin/plugin.json at its root.
  2. Append an entry to plugins with a url source. Add "ref": "v1.0.0" to pin a tag.
  3. Validate, commit and push the marketplace repo.
  4. Users run /plugin marketplace update rajib-skill-marketplace to see the new plugin.

07Roll out to a team

Docs: Register for a repository · Manage plugins for your organization

To give everyone on a project the same plugins, commit the marketplace and the enabled plugins to the project's .claude/settings.json. Claude Code registers the marketplace for each teammate who trusts the folder, and each of them installs the plugin on their own machine.

.claude/settings.json
{
  "extraKnownMarketplaces": {
    "rajib-skill-marketplace": {
      "source": {
        "source": "github",
        "repo": "rajib76/rajib-skill-marketplace"
      }
    }
  },
  "enabledPlugins": {
    "hello-plugin@rajib-skill-marketplace": true
  }
}

Choosing Install for all collaborators on this repository (project scope) in /plugin writes these entries for you. From the command line, use --scope project:

terminal
claude plugin marketplace add rajib76/rajib-skill-marketplace --scope project
claude plugin install hello-plugin@rajib-skill-marketplace --scope project

For a whole company, an administrator can put the same extraKnownMarketplaces and enabledPlugins keys in managed settings, turn on auto-update for everyone, and restrict which marketplaces people can add. On Team and Enterprise plans, the marketplace can also be synced through claude.ai organization settings, so users' git credentials aren't involved.

08Release updates

Docs: Keep users up to date · Versions and updates

Users get a new copy of a plugin only when its version changes. The version comes from plugin.json first, then from the marketplace entry. Pick one approach:

  • Bump version on each release. Users stay on their cached copy until the string changes. If you push new commits but leave "version": "1.0.0", users don't get them.
  • Leave version out of both plugin.json and the entry. Users then track your commits.
  1. Change the plugin and bump version in its plugin.json, for example 1.0.0 → 1.1.0.
  2. Push the plugin repo, then the marketplace repo if you changed it.
  3. Users run /plugin marketplace update <name> in a session, or claude plugin update <plugin>@<marketplace> in the shell.

Background auto-update is off by default and marketplace.json can't turn it on. Each user enables it under Marketplaces in /plugin → Enable auto-update, or an admin sets "autoUpdate": true in managed settings.

To control exactly what users get, tag releases in the plugin repo and pin the entry with "ref": "v1.1.0". For stable and early-access tracks, host two marketplaces with different names whose entries point at different refs.

Renaming or removing a plugin

Changing a plugin's name breaks every existing install. To change only the label people see, set displayName in plugin.json. If you must rename or remove one, add a top-level renames map such as {"formatter": "code-formatter", "legacy-linter": null} so Claude Code migrates existing users.

09Troubleshooting

Docs: Troubleshoot plugins · Grant access to a private marketplace

“git@github.com: Permission denied (publickey)”

This came up while building the GitHub example. For a GitHub owner/repo source, the docs say Claude Code probes ssh -T git@github.com, clones over SSH when the probe succeeds, and falls back to HTTPS otherwise. On a machine with a partial SSH setup (here, a known_hosts file but no key registered with GitHub), the install still failed with this error.

Fix

As the marketplace owner, use a url source with the HTTPS address: {"source": "url", "url": "https://github.com/rajib76/hello-plugin.git"}. The docs confirm an https:// URL always clones over HTTPS, and a public repo needs no credentials. As a user, set CLAUDE_CODE_PLUGIN_PREFER_HTTPS=1 to skip the SSH probe for github sources.

git push returns 403

The credential git has saved for github.com belongs to a different account, or its token has expired. If you use the GitHub CLI, gh auth setup-git tells git to use your gh login.

Plugin not found when installing

Check the id. It's <entry name>@<marketplace name>, both taken from the JSON name fields. Run claude plugin marketplace list to see the marketplace names you've added. If the entry name differs from the name in plugin.json, installing by the manifest name fails with Plugin "<name>" not found in marketplace.

“Source path does not exist”

A relative source points at a folder that isn't there. Validation passes in this case, so the error only appears at install. Write the path from the marketplace root.

“The name '…' is reserved for official Anthropic marketplaces”

Your marketplace uses one of Anthropic's names, such as claude-plugins-official. Rename it.

Skill never triggers

Make the description in SKILL.md more specific about when to use it. Start a new session after installing, and confirm the plugin is enabled with claude plugin list.

Changes don't show up

For a hosted marketplace, bump the plugin version, run /plugin marketplace update, and update the plugin. For a local-folder marketplace, run /reload-plugins. Check the Errors tab in /plugin for load errors.
